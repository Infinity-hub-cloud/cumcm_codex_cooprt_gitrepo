# 问题1 B0/B1 人工运行说明

## 1. 权限与结果边界

本实现依据 `HUMAN-OVERRIDE-CODE-001 = CONFIRMED` 生成。Codex 本轮只完成代码、配置、断言、测试和静态审查，没有执行正式问题1求解，也没有生成任何真实 `result1_candidate.xlsx`。

人工运行产生的内容必须标记为 `HUMAN_RUN_UNREVIEWED_CANDIDATE`，在人工核验求解日志、全部断言及 Excel 回读报告前，不是最终比赛结果。不得覆盖官方 `C题/附件/附件5/result1.xlsx`，不得自动进入问题2。

## 2. 锁定口径

- 模型：`M1-Q1-MILP-v1.3-instant-left-hold`
- 数据：`PREP-TIME-REV-20260911T170805+0800`
- 模板顺序：`G_1,G_2,...,G_143,G_144`，禁止循环平移。
- 自然日观察顺序：`G_144,G_1,...,G_143`，仅用于自然日汇总。
- `S[143]`（数学记号 `S_{T-1}`）为次日 00:00，固定为 6000 kWh。
- `S[144] = S[0]`，即次日 00:10 与当日 00:10 周期衔接。
- 充、放电效率分别为 0.9，往返效率为 0.81。
- 充电区间上限为 `charge_power_max * delta_t`，放电同理；程序不以显示值 `833.3333` 作内部判断。

## 5. 正式附件 B0/B1 人工运行命令

选择一个从未存在的新目录名。以下 PowerShell 片段同时将控制台输出保存到正式运行目录外的独立日志，避免因预先创建运行目录而触发覆盖保护：

```powershell
$runId = Get-Date -Format 'yyyyMMdd_HHmmss'
New-Item -ItemType Directory -Path human_run_logs -Force
python -m q1_baseline.cli --config config/q1_baseline.json run --output-dir "runs/q1_human_run_$runId" 2>&1 |
  Tee-Object -FilePath "human_run_logs/q1_human_run_$runId.console.log"
$LASTEXITCODE
```

这是唯一会进入 B1 Solver 的入口。运行器拒绝覆盖已有目录，并在 Solver 不可用、非最优、断言失败或回读失败时退出。`$LASTEXITCODE` 必须为 `0` 才能进入人工审查；非零时只反馈失败文件和日志，不得补填或手工修改候选结果。只有内部断言全部通过后才会复制官方模板并生成候选文件。

## 6. 每次运行输出

成功运行目录应包含：

- `run_manifest.json`：输入/配置哈希、环境、Git 只读快照、Solver 信息和候选状态；
- `config_snapshot.json`：本次配置快照；
- `dispatch_timeseries.csv`：原模板顺序的负荷、光伏、B0、B1与SOC；
- `metrics_summary.csv`：B0/B1指标长表；
- `assertions.json`：全部程序断言；
- `solver.log`：Solver 原生日志；
- `warnings_and_failures.log`：警告或失败；
- `result1_candidate.xlsx`：独立候选文件，绝非官方结果；
- `export_validation.json`：候选工作簿回读验证；
- `human_feedback.md`：人工审查回填模板。

## 7. 强制断言

内部结果断言包括：数值有限、购电/充电/放电/弃光非负、SOC上下界、充放电精确物理上限、二进制整数性、无同时充放电、逐时段能量平衡、SOC递推、00:00初末SOC、00:10周期闭合、目标值重算、日总能量核对、B1费用不高于B0、Solver最优状态及 MIP gap。

导出回读断言包括：候选与官方模板路径分离、文件存在、工作表名与维度、144个标签及原序映射、无空值、四位小数格式、自然日六个4小时充放电汇总、00:00/24:00 SOC、无公式及官方模板仍存在。导出前后还比较官方模板 SHA-256，发现变化即失败。

## 9. 人工核验顺序

1. 记录 Python 版本、`pip show highspy` 输出和 `doctor` 输出；`highspy_available` 必须为 `true`。
2. 执行 `validate-input`，确认 144 行和四个锁定时段：`0:10-0:20`、`0:20-0:30`、`23:50-0:00+1`、`0:00+1-0:10+1`。
3. 执行普通单元测试。默认的 Solver 集成测试应显示 `REQUIRES_HUMAN_RUN`；只有人工明确需要时才开启 toy Solver 测试。
4. 执行一次正式 B0/B1 命令，不重用已有运行目录，不中途编辑输入、配置或输出文件。
5. 核验 `run_manifest.json` 的输入/配置哈希、模型版本、数据版本和 Solver 最优状态。
6. 核验 `assertions.json` 中 B0、B1 均为 `passed: true`；B1必须包含 `solver_status_optimal`、`mip_gap` 与 `b1_cost_not_above_b0` 的通过记录。
7. 核验 `export_validation.json` 为 `passed: true`，并确认 `result1_candidate.xlsx` 位于本次运行目录而非官方附件目录。
8. 阅读 `solver.log` 与 `warnings_and_failures.log`。任何 ERROR、非最优终止、断言失败或回读失败均停止，状态仅能标为“结果待回填/待人工处理”。
9. 填写 `human_feedback.md`，连同下节的完整反馈包提交人工负责人；在负责人确认前，结果只能称为候选结果。
