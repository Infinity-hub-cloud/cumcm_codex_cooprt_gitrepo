# 问题1 B0/B1 人工运行说明

## 1. 权限与结果边界

本实现依据 `HUMAN-OVERRIDE-CODE-001 = CONFIRMED` 生成。Codex 本轮只完成代码、配置、断言、测试和静态审查，没有执行正式问题1求解，也没有生成任何真实 `result1_candidate.xlsx`。

人工运行产生的内容必须标记为 `HUMAN_RUN_UNREVIEWED_CANDIDATE`，在人工核验求解日志、全部断言及 Excel 回读报告前，不是最终比赛结果。不得覆盖官方 `C题/附件/附件5/result1.xlsx`，不得自动进入问题2。

## 2. 锁定口径

- 模型：`M1-Q1-MILP-v1.3-instant-left-hold`
- 数据：`PREP-TIME-REV-20260911T170805+0800`
- 模板顺序：`G_1,G_2,...,G_143,G_144`，禁止循环平移。
- 自然日观察顺序：`G_144,G_1,...,G_143`，仅用于自然日汇总。
- `S[143]`（数学记号 `S_{T-1}`）为次日 00:00，固定为 6000 kWh。
- `S[144] = S[0]`，即次日 00:10 与当日 00:10 周期衔接。
- 充、放电效率分别为 0.9，往返效率为 0.81。
- 充电区间上限为 `charge_power_max * delta_t`，放电同理；程序不以显示值 `833.3333` 作内部判断。

## 5. 正式附件 B0/B1 人工运行命令

选择一个从未存在的新目录名，例如：

```powershell
python -m q1_baseline.cli --config config/q1_baseline.json run --output-dir runs/q1_human_run_YYYYMMDD_HHMMSS
```

这是唯一会进入 B1 Solver 的入口。运行器拒绝覆盖已有目录，并在 Solver 不可用、非最优、断言失败或回读失败时退出。只有内部断言全部通过后才会复制官方模板并生成候选文件。

## 6. 每次运行输出

成功运行目录应包含：

- `run_manifest.json`：输入/配置哈希、环境、Git 只读快照、Solver 信息和候选状态；
- `config_snapshot.json`：本次配置快照；
- `dispatch_timeseries.csv`：原模板顺序的负荷、光伏、B0、B1与SOC；
- `metrics_summary.csv`：B0/B1指标长表；
- `assertions.json`：全部程序断言；
- `solver.log`：Solver 原生日志；
- `warnings_and_failures.log`：警告或失败；
- `result1_candidate.xlsx`：独立候选文件，绝非官方结果；
- `export_validation.json`：候选工作簿回读验证；
- `human_feedback.md`：人工审查回填模板。

## 7. 强制断言

内部结果断言包括：数值有限、购电/充电/放电/弃光非负、SOC上下界、充放电精确物理上限、二进制整数性、无同时充放电、逐时段能量平衡、SOC递推、00:00初末SOC、00:10周期闭合、目标值重算、日总能量核对、B1费用不高于B0、Solver最优状态及 MIP gap。

导出回读断言包括：候选与官方模板路径分离、文件存在、工作表名与维度、144个标签及原序映射、无空值、四位小数格式、自然日六个4小时充放电汇总、00:00/24:00 SOC、无公式及官方模板仍存在。导出前后还比较官方模板 SHA-256，发现变化即失败。
