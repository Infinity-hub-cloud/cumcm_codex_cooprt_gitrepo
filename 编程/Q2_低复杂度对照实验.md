## 2. 固定四组实验

| 标识 | 负载点预测 | 光伏点预测 | 规划缓冲 |
|---|---|---|---|
| baseline | 最近已完成同刻 | 最近已完成同刻 | 无 |
| weekday | 最近已完成且与目标自然日同星期、同刻；不足则退回最近同刻 | 最近已完成同刻 | 无 |
| recent_buffer | 最近已完成同刻 | 最近已完成同刻 | 历史净负荷误差正分位数 |
| weekday_buffer | 同weekday | 最近已完成同刻 | 使用该点预测器自身的历史误差 |

每组都独立重放365个模板日，独立推进SOC，并同时计算其匹配的无储能B0与储能B1。配对差异为：baseline→weekday检验负载预测，baseline→recent_buffer检验缓冲，weekday→weekday_buffer检验缓冲的附加效果。第四组同时相对baseline变化两项，不作单因素归因。

这次不扫描窗口、分位数或大量模型。四组和参数在新增实验运行前固定。既有全年基线统计已被观察，因此本次属于探索性消融，不能包装为完全未见数据的留出验证；也不根据全年最省的组自动选择正式模型。如之后调参，必须仅使用决策时刻之前已完成的数据进行滚动验证，或预先固定后续时间块。

## 3. 风险缓冲的数学含义

对目标同一自然时钟的过去区间，重建它当时0:00可获得的点预测。历史净负荷误差为

$$e_{h,t}=(L_{h,t}-P_{h,t})-(\widehat L_{h,t}-\widehat P_{h,t}).$$

只有该真实区间结束时间不晚于当前0:00，且位于最近28天内，才纳入校准；不使用冷启动无历史样本。历史预测本身也只能使用其原决策时刻已经结束的区间。每个时钟至少7个有效样本才启用

$$b_{d,t}=\max\{0,Q_{0.8}(e_{h,t})\};$$

不足7个样本时缓冲为0。单独形成规划量

$$L^{\mathrm{plan}}_{d,t}=\widehat L_{d,t}+b_{d,t}.$$

原负载、光伏以及点预测字段均保留，缓冲不是虚构实际负载。MILP对上述规划负荷求解；真实回放仍使用未经修改的实际负载、光伏、固定G/C/D和原R0正部结算。

选择0.8的依据：在简化的单时段、固定储能动作、无售电且计划电费始终支付的模型中，设实际净需求为N，计划q的期望费用是

$$J(q)=\pi q+5\pi\,\mathbb E[(N-q)_+].$$

连续分布且内点最优时，导数为零得到$F_N(q)=1-1/5=0.8$。它提供低复杂度候选的经济依据，不能证明此28天残差估计或跨期储能策略全局最优，也不构成可靠性80%的统计保证。缓冲过大可能导致计划购电过量、弃能上升和总费用变高，必须保留不利结果。

## 4. 不变的口径

- 仅读取现有锁定哈希的附件1固定电价、附件2真实数据和官方result2模板。附件3/4不进入问题二。
- 0:00生成计划，只允许`source_interval_end <= decision_time`；目标slot144仍对应次日0:00–0:10。weekday对该目标使用次日的星期，不以模板日期的星期替代。
- 1月1日144段、1月2日slot144的冷启动规则保留。缺历史段的G/C/D与缓冲均为0。
- 每组从1月1日同一初始SOC推进；2月1日不重置。0:00–0:10沿用前一模板日已承诺动作，Q2无每日SOC回6000约束。
- kW乘1/6变成kWh。原始数据、预处理CSV、模板标签不改；现有输入舍入容差不挪作可行性容差。
- 充放电效率各0.9、母线侧C/D、SOC1200–10800、功率5000、互斥、计划费和五倍紧急购电费全部一致。不增加售电、退款、事后修改计划或未来信息。
- 经济比较沿用模板日输出窗口（2月1日0:10至次年1月1日0:10）；预测评价和储能汇总沿用既有自然日接口。两类口径不得混算，跨窗口的首末10分钟不重复计费。
- 各组可能从预热获得不同2月初SOC；报告保留正式期首末SOC。后续引入终端价值时需要单独对照，不能以异常末期透支冒充降本。

## 5. 新字段和输出

`predictions_load.csv`/`predictions_pv.csv`中的`predicted_kw`仍是点预测。新增`load_source_interval_start/end`给出负载来源（原`source_interval_start/end`对候选对应光伏来源），`planning_load_kw`、`risk_buffer_kw`、`buffer_sample_count`、`buffer_source_start/end`给出缓冲审计信息。校准窗口端点指残差真实目标区间；其原预测来源可按固定算法和锁定输入重建。

`dispatch_timeseries.csv`追加`risk_buffer_kwh`及`planning_load_kwh`，原`load_pred_kwh`继续保持点预测。规划平衡用planning字段；实际平衡仍用actual字段。预测MAE、RMSE等继续评价点预测，不把人为风险裕度算成预测器输出。

每个实验目录保留原17件反馈文件、完整Solver日志和独立`result2_candidate.xlsx`；不覆盖官方文件。模型ID、预测ID、实验名和固定参数写入manifest。公共Q1求解接口与Q2代码哈希同时登记。suite目录新增：

| 文件 | 用途 |
|---|---|
| experiment_manifest.json | 四组完成状态、固定实验身份、失败信息 |
| comparison_report.md | 自动生成的经济对比简报 |
| comparison_summary.csv | 8条方案（四组×有/无储能）的费用、节省、日费用P95、首末SOC |
| comparison_monthly.csv | 逐月计划费、紧急费、总费、弃能和配对节省 |
| comparison_daily.csv | 逐日配对结果；支持排查最差日 |
| comparison_prediction_metrics.csv | 合并四组原始点预测的overall/month/season误差 |
| comparison_solver.csv | 冷启动天数、最优天数、非最优天数、gap、Solver时间和告警 |

比较同时区分相对旧B0、旧B1的总收益，以及相同预测与缓冲下B1相对匹配B0的储能增益。不能把预测器改善全部归因于储能。负数节省表示变差。成本最小不必同时意味着弃能最少或预测MAE最低。

## 6. 人工执行

先进入本机的共享工作区`编程`目录，使用已运行Q2的同一Python和HiGHS环境。

```powershell
python -m unittest discover -s tests -v
python -m q2_baseline.cli validate-input --config config/q2_baseline.json
$q2ComparisonStamp = Get-Date -Format 'yyyyMMdd_HHmmss'
$q2ComparisonOutput = "runs/q2_low_complexity_$q2ComparisonStamp"
python -m q2_baseline.experiments --config config/q2_baseline.json --output-dir $q2ComparisonOutput
if ($LASTEXITCODE -ne 0) { throw 'Q2 comparison failed; inspect experiment_manifest.json and failed arm logs' }
Write-Output $q2ComparisonOutput
```

程序拒绝覆盖已有suite目录。四组顺序运行，每组包含364次日MILP和一次冷启动；耗时高于单次基线，不能把单日求解器耗时当成整个实验耗时。任何一组失败都保留已有反馈，停止后续组和总汇总，不混合不同配置的运行包。

仅单独运行一组时：

```powershell
python -m q2_baseline.cli run --config config/q2_baseline.json --experiment weekday_buffer --output-dir runs/q2_weekday_buffer_unique
```

四组完整存在后重新生成汇总（仅覆盖该suite的派生comparison文件，不重求解）：

```powershell
python -m q2_baseline.experiments --output-dir $q2ComparisonOutput --summarize-only
```

## 7. 人工反馈与升级判定

反馈整个suite目录；先看`comparison_report.md`和六个comparison文件，再复核每组断言、候选回读和反馈表。baseline重跑总费用应与旧运行约22835273.5064元一致；若不同，先检查求解器版本、代码、哈希和可替代最优轨迹，不能直接以新旧差额声称改进。

升级至少要求：总真实费用下降、无未来信息使用、无约束或模板回读失败；同时披露最差月份、改善日/月数量、紧急购电、剩余能量、预测误差和首末SOC。即使某一方案最省，也需说明增加的规则是否值得其收益。保持四组全部结果；不自动替换基线，不根据单日成功进入问题三。

若这些简单方案仍不足，后续依次考虑：低维工作日/周末回归、纯历史滚动选窗、保持0:00购电计划固定的储能实时纠偏、跨日规划终端价值、少量历史误差情景的期望结算费用优化。后三项会改变执行或规划层，需要另登记模型版本并作同规则对照。完美预知Oracle仅能用于事后参考；目前尚无依据承诺能把费用压到某一具体金额。
