```powershell
$q3Root = "runs/q3_$q3Stamp"
```

## 6. 价值分解

```powershell
python -m q3_baseline.cli --config config/q3_baseline.json compare `
  --reference-metrics "$q3Root/REF_Q2_FROZEN/q2_reference_metrics_summary.csv" `
  --initial-metrics "$q3Root/Q3_ATTACHMENT3_0ONLY/metrics_summary.csv" `
  --rolling-metrics "$q3Root/Q3_ROLLING_4ISSUE/metrics_summary.csv" `
  --no-storage-metrics "$q3Root/Q3_NOSTORAGE_REFERENCE/metrics_summary.csv" `
  --output "$q3Root/value_decomposition.json"
if ($LASTEXITCODE -ne 0) { throw 'Q3 value decomposition failed' }
```

比较器会按`model_id=M2-Q2-EXPERIMENT-weekday_buffer-v1.0`、
`baseline_id=B1_WEEKDAY_BUFFER_MILP_R0`和`formal_output`精确选取Q2引用，
不会误取同一CSV中排在前面的B0。输出同时给出总价值，以及计划费、调整费、
紧急购电费/电量、弃能和储能吞吐的“基线减候选”分解；正值表示候选减少该项。

如需减少官方更新次数的消融，可另外运行全新目录：

```powershell
python -m q3_baseline.cli --config config/q3_baseline.json run `
  --track Q3_ROLLING_4ISSUE --issue-set 0_12 `
  --output-dir "$q3Root/Q3_ISSUESET_0_12"
```

不得创建3:00、9:00等不存在的预测版本。

## 9. 已知故障修复记录

- `Q3-SOC-FLOAT-001`：滚动求解边界处可能返回位于物理边界外、但仍在
  `feasibility_tolerance=1e-6`内的浮点SOC。当前实现会先验证其仍在容差带内，
  再吸附到精确的1200或10800 kWh；超过容差的越界继续Hard Fail。
- `Q3-A3-LOOKUP-001`：旧版滚动查询会为每个待执行区间扫描全部Attachment3
  映射行，全年四时点运行会产生数量级过大的重复比较。当前实现已按物理区间建立
  索引；Q3默认不再逐子问题向控制台输出HiGHS详情，只显示月度进度，详细日志写入
  运行目录。
- 任何代码修复后，正式公平对照推荐使用新的`$q3Stamp`重跑四轨道，保证同一批次
  使用完全相同的源代码。旧失败目录必须保留，不得覆盖。
