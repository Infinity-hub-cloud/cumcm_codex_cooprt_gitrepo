# CUMCM paper workspace rules

When the task is paper writing, use the installed CUMCM paper skills and existing `math-modeling-paper-pro`; use `sepia` only after scientific facts are locked.

Treat solver/program outputs as science authority. Never silently change models, equations, objectives, constraints, units, numerical results, causal status, or optimality status.

Prefer `.paper/paper_context.md` and its source pointers over rescanning the whole repository. Re-open original files only when a fact, equation, result, or conflict must be verified.

Write one paper spine, not isolated mini-papers. Define shared mathematics once. In later questions write only the delta, answer, interpretation, attached validation, and boundary.

Missing evidence in a first draft should become an explicit `TODO[证据缺口: ...]`; never invent it. Finish all sections that are supportable.
